# Top K 问题：三大策略的权衡

Top K 是面试中最能体现“场景分析能力”的题目。没有最好的算法，只有最适合场景的解法。

## 1. 核心解法对照表

| 解法 | 时间复杂度 | 空间复杂度 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **内置 sort()** | $O(N \log N)$ | $O(\log N)$ | 数据量小、$K$ 接近 $N$、日常开发、力扣快速通关 |
| **最小堆 (Min-Heap)** | $O(N \log K)$ | $O(K)$ | **海量数据**、动态数据流、$K \ll N$ (面试必考) |
| **快速选择 (QuickSelect)** | 平均 $O(N)$ | $O(1)$ | 静态数组、追求理论最优解 (面试高分点) |

## 2. 深度心法：为什么选堆？

很多人面试时上来就说快排，但如果面试官追问：“如果数据量是 10 亿个数，内存放不下怎么办？”

这时候**最小堆**就是唯一的答案：
- **内存友好**：我们不需要把 10 亿个数都加载进内存，只需要维护一个大小为 $K$ 的堆。
- **动态处理**：数据可以像流水一样进来，我们实时更新堆，永远保持堆里是目前最大的 $K$ 个数。

## 3. 快速选择 (QuickSelect) 模板

这是基于快排 `partition` 思想的变种。它的精髓在于：**我们不需要给全员排序，只要把前 K 个数“甩”到数组一边即可。**

```javascript
function findKthLargest(nums: number[], k: number): number {
    // 寻找第 k 大的元素，如果按降序排列，其目标索引应为 k - 1
    const targetIndex = k - 1;

    const quickSelect = (left: number, right: number): number => {
        // 区间内只有一个元素，直接返回
        if (left === right) {
            return nums[left];
        }

        // 1. 随机选择 Pivot，并将其交换到区间最右侧
        const randomIndex = Math.floor(Math.random() * (right - left + 1)) + left;
        [nums[randomIndex], nums[right]] = [nums[right], nums[randomIndex]];
        
        const pivot = nums[right];
        
        // 2. Partition 过程 (降序排列，把比 pivot 大的放到左边)
        let p = left; // p 始终指向下一个“大于等于 pivot”的元素应该存放的位置
        for (let i = left; i < right; i++) {
            if (nums[i] >= pivot) {
                [nums[i], nums[p]] = [nums[p], nums[i]];
                p++;
            }
        }
        // 将 pivot 放到它最终确定的位置 p 上
        [nums[p], nums[right]] = [nums[right], nums[p]];

        // 3. 根据 pivot 的最终位置决定往哪边递归
        if (p === targetIndex) {
            return nums[p]; // 刚好找到第 k 大的元素
        } else if (p < targetIndex) {
            // 目标在 p 的右侧
            return quickSelect(p + 1, right);
        } else {
            // 目标在 p 的左侧
            return quickSelect(left, p - 1);
        }
    };

    return quickSelect(0, nums.length - 1);
}
```

上面的方法是Lomuto分区（可以降低心智负担），也是双指针，但是一个指针由for loop维护，不用人为控制。
Hoare分区也可以，核心思想是一样的。

> 关于 left > right 的疑问
> 你的直觉非常敏锐：如果 j === left，确实会导致传进去的参数变成 left 和 left - 1（即左边界大于右边界）。
> 但是，你的猜测是对的：代码在实际运行中根本走不到那个死角。
> 原因在于，这段代码在递归时始终维护了一个绝对安全的数学边界条件（Invariant）：你要找的 targetIndex 永远被死死夹在当前的 [left, right] 区间内。也就是 `left <= targetIndex <= right` 永远成立。

两者都可以用来实现快速选择 和 快速排序，下面是Hoare分区的版本：

```typescript
function findKthLargest(nums: number[], k: number): number {
    const targetIndex = k - 1;

    const quickSelect = (left: number, right: number): number => {
        if (left === right) return nums[left];

        // 1. 随便抓一个基准值（不需要像单指针那样把它换到末尾去藏起来）
        const randomIndex = Math.floor(Math.random() * (right - left + 1)) + left;
        const pivot = nums[randomIndex];

        // 2. 双指针就位（故意往外扩一格，配合后面的 do-while）
        let i = left - 1;
        let j = right + 1;

        while (i < j) {
            // 降序：左指针寻找比 pivot 小的（这些小家伙不该在左边）
            do { i++; } while (nums[i] > pivot);
            
            // 降序：右指针寻找比 pivot 大的（这些大家伙不该在右边）
            do { j--; } while (nums[j] < pivot);

            // 双方都找到了“叛徒”，交换它们！
            if (i < j) {
                [nums[i], nums[j]] = [nums[j], nums[i]];
            }
        }

        // 3. 循环结束时，指针 j 成了天然的“三八线”！
        // [left, j] 这个区间里的数，全都 >= pivot
        // [j + 1, right] 这个区间里的数，全都 <= pivot
        
        if (targetIndex <= j) {
            return quickSelect(left, j); // 目标在左半区
        } else {
            return quickSelect(j + 1, right); // 目标在右半区
        }
    };

    return quickSelect(0, nums.length - 1);
}
```

出现了大量重复的item在一个测试用例中，导致TLE，解决办法是使用三路划分（Dutch National Flag）（基于Lomuto分区）来处理重复元素

```typescript
function findKthLargest(nums: number[], k: number): number {
    const quickSelect = (left: number, right: number): number => {
        if (left === right) return nums[left];

        // 1. 随机选取基准值
        const pivot = nums[Math.floor(Math.random() * (right - left + 1)) + left];

        // 2. 荷兰国旗三路划分
        let l = left;      // l 的左边都是严格大于 pivot 的
        let r = right;     // r 的右边都是严格小于 pivot 的
        let i = left;      // i 是当前考察的游标指针

        while (i <= r) {
            if (nums[i] > pivot) {
                // 遇到比 pivot 大的，扔到左边去，游标 i 放心往前走
                [nums[i], nums[l]] = [nums[l], nums[i]];
                l++;
                i++;
            } else if (nums[i] < pivot) {
                // 遇到比 pivot 小的，扔到右边去
                // 注意：这里 i 不能动！因为从右边换过来的数还没被检查过
                [nums[i], nums[r]] = [nums[r], nums[i]];
                r--;
            } else {
                // 遇到等于 pivot 的，什么都不用换，游标直接往前走
                i++;
            }
        }

        // 3. 循环结束后，数组被完美切分成了三块：
        // [left, l - 1]   ：全部 > pivot
        // [l, r]          ：全部 === pivot  <-- (防 TLE 的核心区域)
        // [r + 1, right]  ：全部 < pivot

        const targetIndex = k - 1;

        // 4. 判断第 k 大的元素落在哪块区域
        if (targetIndex >= l && targetIndex <= r) {
            // 目标正好在“相等区域”里，直接出结果！不需要再递归了！
            return pivot;
        } else if (targetIndex < l) {
            // 目标在左侧（大于 pivot 的区域）
            return quickSelect(left, l - 1);
        } else {
            // 目标在右侧（小于 pivot 的区域）
            return quickSelect(r + 1, right);
        }
    };

    return quickSelect(0, nums.length - 1);
}
```

（标准的 Hoare 划分本身就是两路的，强行改造成三路会非常反人类。工业界（比如 C 语言库中的 qsort）使用了一种叫 Bentley-McIlroy 三路划分 的神级算法。它依然是左右双指针向中间靠拢，但是遇到等于 pivot 的元素时，会先把它们塞到数组的最左边和最右边。等双指针相遇后，再把两端的相等元素统统**“搬”回数组中间**。）

## 4. 记忆技巧与面试话术

- **求前 $K$ 大用小顶堆**：因为我们要剔除小的，留下大的。小顶堆的堆顶是最小的，发现新数比堆顶大，就踢掉堆顶换新人。
- **求前 $K$ 小用大顶堆**：同理，剔除大的，留下小的。
- **话术建议**：先提 $O(N \log N)$ 的简单解法，然后主动引出“如果是海量数据流”的情况下我会用 $O(N \log K)$ 的堆，最后展示对 $O(N)$ 快速选择的掌握。

> **锻造感悟：** Top K 问题的进化过程反映了计算机科学的核心：**资源置换**。内置排序用时间换简单，堆用空间换处理流数据的能力，而快速选择则通过舍弃不必要的排序顺序来压榨极致的时间效率。
